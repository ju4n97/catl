# Installation

`catl` is distributed as a single static binary with no external libc or runtime dependencies.

Prebuilt binaries for Linux, macOS, and Windows on x86_64 and arm64 are available on the [GitHub releases page](https://github.com/ju4n97/catl/releases).

## System requirements

Local operations have zero external runtime dependencies. Commands that run locally (`catl check`, `catl list`, `catl resolve`, `catl show`, and the Go library) run in scratch or distroless containers without external utilities.

If you update remote Git dependencies with `catl update`, the system `git` binary (version 2.30+) must be available on your `PATH`. If `git` is missing, only remote mutation commands fail; offline validation and inspection remain functional.

## Linux and macOS

```bash
curl -fsSL https://raw.githubusercontent.com/ju4n97/catl/refs/heads/main/scripts/install.sh | bash
```

The script installs the binary to `/usr/local/bin/catl`, or `$HOME/.local/bin/catl` when running without root permissions.

## Windows

```powershell
irm https://raw.githubusercontent.com/ju4n97/catl/refs/heads/main/scripts/install.ps1 | iex
```

## Verify artifact integrity

Release assets include SHA-256 digests in `checksums.txt`:

```bash
curl -fsSLO https://github.com/ju4n97/catl/releases/latest/download/checksums.txt

# Linux
sha256sum --ignore-missing --check checksums.txt

# macOS
shasum -a 256 --ignore-missing -c checksums.txt
```

## Build from source

### Using Go install

Requires Go 1.27+:

```bash
go install github.com/ju4n97/catl/cmd/catl@latest
```

Ensure `$GOPATH/bin` or `$HOME/go/bin` is in your `PATH`.

### From source with Task

Requires [Task](https://taskfile.dev):

```bash
git clone https://github.com/ju4n97/catl.git
cd catl
task build
# Binary is generated at bin/catl
```

## Container images

Two container variants are published to GitHub Container Registry for `linux/amd64` and `linux/arm64`:

| Image tag                 | Base              | Included tools                 | Best for                                                          |
| ------------------------- | ----------------- | ------------------------------ | ----------------------------------------------------------------- |
| `latest` (or `<version>`) | Distroless static | Only `catl` binary             | CI checks (`catl check`), HTTP servers (`catl serve`), Kubernetes |
| `latest-alpine`           | Alpine Linux      | `catl`, `git`, CA certificates | Containerized CI runners executing `catl update`                  |

### Default distroless image

The default image has no shell or package manager, keeping image sizes small (~18 MB) with zero CVE footprint:

```bash
docker run --rm -v "$(pwd):/catalog" ghcr.io/ju4n97/catl:latest -C /catalog check
```

This image supports all local validation and inspection commands (`check`, `list`, `resolve`, `show`, `serve`).

### Alpine image with Git

If your CI pipeline runs entirely inside Docker and needs to fetch or update remote Git dependencies, use the `latest-alpine` image:

```bash
docker run --rm -v "$(pwd):/catalog" ghcr.io/ju4n97/catl:latest-alpine -C /catalog update
```

## Shell autocompletion

`catl` supports completion for subcommands and flags.

### Bash

Add this to `~/.bashrc`:

```bash
echo 'complete -o default -C catl catl' >> ~/.bashrc
source ~/.bashrc
```

### Zsh

Add this to `~/.zshrc`:

```zsh
autoload -Uz +X compinit && compinit
autoload -Uz +X bashcompinit && bashcompinit
complete -o default -C catl catl
```

### Fish

Save completion to `~/.config/fish/completions/catl.fish`:

```fish
complete -c catl -f -a '(catl --generate-shell-completion (commandline -cop))'
```

## Man pages

Package manager installations (`.deb`, `.rpm`, `.pkg.tar.zst`) install man pages automatically.

To install the man page manually:

```bash
sudo mkdir -p /usr/local/share/man/man1
sudo curl -fsSL https://raw.githubusercontent.com/ju4n97/catl/main/man/catl.1 \
  -o /usr/local/share/man/man1/catl.1
sudo mandb 2>/dev/null || true
```

View the manual:

```bash
man catl
```
