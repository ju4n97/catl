# Identifiers

Every entity in `catl` is addressed using a qualified identifier that pairs a namespace with an entity ID:

```text
namespace.id
```

```text
clinical.emergency-guide
├── namespace: clinical (catalog name)
└── id: emergency-guide (filename or bundle directory name)
```

## Identifier grammar

Catalog names, collection names, dependency names, and entity IDs all share the same grammar:

```text
^[a-z0-9]+(-[a-z0-9]+)*$
```

An identifier must be between 1 and 63 ASCII characters long. It consists of lowercase letters (`a-z`) and digits (`0-9`), with words separated by single hyphens (`-`).

Identifiers can't start or end with a hyphen. Uppercase letters, dots, and underscores are not permitted. Because dots are forbidden in names, a qualified identifier always splits cleanly on its single dot into `namespace` and `id`.

```bash
# Valid identifiers
clinical
patient-records
v2-api
rule-101

# Invalid identifiers
Clinical        # Contains uppercase letters
patient_records # Underscores are forbidden
patient..triage # Dots are forbidden
-triage         # Can't start with a hyphen
```

## Namespaces

A catalog's primary namespace is its `catalog.name` declared in `catl.toml`:

```toml title="catl.toml"
[catalog]
name = "clinical"
```

All local entities in this catalog belong to the `clinical` namespace.

When a catalog declares dependencies in `catl.toml`, each dependency key defines an external namespace. The key must match the target catalog's own `catalog.name`:

```toml title="catl.toml"
[dependencies]
shared-infra = { git = "https://github.com/acme/shared-infra", tag = "v1.4.0" }
```

Entities imported from this dependency belong to the `shared-infra` namespace.

## Qualified IDs

A qualified ID joins the namespace and entity ID with a dot:

```text
clinical.triage
shared-infra.postgres
```

`catl` doesn't accept bare IDs in CLI commands or API calls. You can't ask `catl` to resolve `triage`; you must specify `clinical.triage`.

This rule eliminates ambiguity. The identifier means the same thing regardless of your current shell directory or which catalog you have open. If you pass a bare ID to a command, `catl` rejects it with a hint:

```bash
catl resolve protocols triage
```

```text
catl: "triage" is not a qualified ID (want namespace.id); did you mean "clinical.triage"?
```

## Collection scoping

Qualified IDs are unique within a collection, but not across different collections.

For example, a catalog can define both a `protocols` collection and a `monitors` collection. Both collections can have an entity with the ID `heart-rate`:

```text
clinical-catalog/
├── protocols/
│   └── heart-rate.yaml   # Qualified ID: clinical.heart-rate
└── monitors/
    └── heart-rate.yaml   # Qualified ID: clinical.heart-rate
```

Because of this, lookups in both the CLI and Go API require both the collection name and the qualified ID:

```bash
# In the CLI
catl resolve protocols clinical.heart-rate
catl resolve monitors clinical.heart-rate
```

```go
// In Go
proto, err := cat.Resolve("protocols", "clinical.heart-rate")
mon, err := cat.Resolve("monitors", "clinical.heart-rate")
```

The collection acts like a section in a Unix manual page (`printf(1)` vs `printf(3)`). The qualified ID identifies the entity within that collection.
